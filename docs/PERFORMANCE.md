# 軽量・高速化メモ

測っていないことは「未測定」と書きます。数値は GitHub Actions の Linux ランナー
（dev プロファイル、1回だけの実行）で `tests/engine_perf_tests.rs` が出した値です。
Windows 実機や GUI のフレーム時間ではありません。

## すでにあったもの（このPRより前から main にある）

- ノード単位のキャッシュと増分評価（`src/engine.rs`）。入力と設定が同じノードは再計算せず、
  変えたノードの下流だけ計算します。
- 評価は別スレッド（`src/app.rs` の `Worker`）で動き、新しい編集が来ると古い計算を止めます（キャンセル）。
- 同じ階層の独立ノードは並列に評価します（結果は順番に依存しません）。
- 3D表示のシーンキャッシュ、メッシュ上限（20万三角形）、画面外三角形の除外、1枚のメッシュへの一括描画。
- データツリー表示は枝を開いたときだけ中身を作り、表示行数は最大500行です（`src/data_view.rs`）。
- リリースビルドは `lto = "fat"`、`strip = true`。

## 実測できたこと（`tests/engine_perf_tests.rs`、1回の値）

2000ノードの足し算チェーン:

| 操作 | 時間 | 再計算/キャッシュ |
|---|---|---|
| 初回 | 8.3 ms | 2000 / 0 |
| 何も変えず再評価 | 3.2 ms | 0 / 2000 |
| 最後の1ノードだけ変更 | 3.2 ms | 1 / 1999 |
| 最初のノードを変更 | 7.1 ms | 2000 / 0 |

- 最後の1ノードだけ変えても約3 msかかります。ノード数に比例する準備（キー照合と結果コピー）が残っているためです。
  再計算そのものは1ノードだけです。ここは今後の改善余地で、このPRでは変えていません。
- 50回確認したところでキャンセルすると、6ノード計算した時点で 0.9 ms で止まり、
  その後の完全評価は新しい評価器の結果と一致しました。
- 48個の独立した球ノード: 1スレッド 1.4 ms、8スレッド 1.3 ms。ノードが軽いので並列の利点は見えていません（結果は一致）。
  重いノードでの効果は未測定です。

テストの時間上限は 20 秒とごく緩く、遅いCIでも落ちません。数値は
`cargo test --test engine_perf_tests -- --nocapture` で確認できます。
