## 実画面で確認したこと

- 起動直後に「ねじれの花器」と編集可能なノードが表示される。
- 花器の半径スライダーを変えると、ノードの値と3D形状が更新される。
- 連続したスライダー操作を、Undoボタン1回で戻せる。
- ノード選択に応じて右下の設定欄が切り替わる。
- メッシュ出力を数値入力につなごうとすると日本語で拒否し、元の配線が保たれる。
- アプリ内のファイル選択で日本語名の`.morph`を保存し、保存完了が表示される。
- 保存後に半径を変え、保存済み作品を開き直す。未保存変更の確認を経て、保存時の数値と形状へ戻る。
- 書き出し前に11,808三角形・開いた辺0・非多様体の辺0を表示し、花器をSTLへ書き出せる。
- 作品例一覧から「輪郭からロフト」を開くと、数列・円・移動・ロフトの6ノードと結果が表示される。
- 同梱日本語フォントをTrueTypeへ変更した後、「高さ」「回転面」などが欠落せず表示される。

最初のOS標準ファイルダイアログは、検証環境に必要なサービスがないと操作を待たせたため、依存を削除し、アプリ内のファイル選択へ置き換えました。配布版にはそのOSダイアログ依存を含めません。

上記の実画面確認は主にマウス操作です。キーボードショートカット全種類、日本語IMEの実入力、タッチ操作、スクリーンリーダーによる操作は未検証です。

## 作品例の生成・書き出し

`Morphlet --export-demos examples` で、同じエンジンから6作品を生成しました。メッシュの5作品はSTL出力に成功しています。

| 作品 | 三角形 | 開いた辺 | 出力 |

| 光のリング | 12,160 | 0 | `.morph` / STL |
| 星のトーテム | 1,144 | 0 | `.morph` / STL |

「開いた辺0」は製造の保証ではありません。自分で変更した形状や、相互に重なる形状は、自己交差・最小肉厚・造形条件を別途確認する必要があります。STLを読む側ではmmとして解釈してください。

## Windows用バイナリ

生成コマンドの中心部分は次のとおりです。Windows上でMSVCを使う通常のビルド手順はREADMEに記載しています。

```sh
RUSTFLAGS='-C target-feature=+crt-static' cargo build --release --locked --target x86_64-pc-windows-gnullvm --bin Morphlet
```

LLVM MinGWの対応リンカーを指定してクロスコンパイルしています。PEヘッダーはx86-64 / PE32+ / Windows GUIです。DLLインポートを確認し、WindowsのシステムDLL以外の追加ランタイムDLLへの依存は見つかっていません。RhinoやGrasshopperのランタイムへの依存もありません。コード署名は付けていません。

これらはWindows実機での起動や、特定PCのGPUドライバーとの相性を保証する確認ではありません。FPS、起動秒数、大規模グラフの性能保証は計測・公表していません。

## 残る実装上の制約

- NURBS/B-rep、STEP/3DM、GH/GHX/GHA互換、ブーリアン、AI生成は未実装。
- 複雑な交差面の3D表示は、面の平均深度による描画順のため不正確になる場合がある。
- 外部メッシュ・曲線の読み込みは未実装。保存した`.morph`と作品例から編集する。
- 復旧ファイルは1つ。複数ウィンドウの独立した復旧履歴は提供しない。
- 変更履歴やカメラ姿勢は`.morph`へ保存しない。Undoは現在の起動中の履歴。
- 自動保存の成功はOSの書込権限に依存する。作業は明示的な`.morph`保存で残す。
