# 厳密 NURBS / B-rep / SubD の速さ（実測）

`cargo run --example nurbs_benchmark` で測った値です。各操作で数回測り、最も速い値を載せています。

## 2026-11-28（ブランチ `feat/nurbs-2`）

- マシン: Intel Xeon 2.10 GHz、2 スレッド、メモリ 7 GB（クラウドの作業環境）
- コンパイラ: rustc 1.97.0
- プロファイル: `dev`（NODES 本体 opt-level 1、依存クレートと SolidCraft は opt-level 2、デバッグ情報なし）。リリースビルド（`--release`、LTO）では測っていません。

| 操作 | 時間 |
|---|---|
| 直方体 40×30×20（作成とメッシュ化） | 0.4 ms |
| 12 本の稜線すべてにフィレット r=3 | 51.9 ms |
| 交差する 2 本の円柱（r10 と r6）の和 | 4,778 ms |
| 同じ 2 本の円柱の厳密な交線 | 3,762 ms |
| 同じ交線をメッシュから近似した場合 | 1.3 ms |
| 円柱のカップのシェル t=2（曲面の中空化） | 52.6 ms |
| SubD 箱ケージを 2 回細分（96 枚）→ B-rep | 68.5 ms |
| T-spline の花器ケージ → B-rep | 95.3 ms |
| 拘束スケッチ（穴あき板）を解く | 0.1 ms |
| フィレット付きの箱を 12 個に円形配列（並列） | 238.7 ms |
| 同じ配列を 1 個ずつ作った場合（逐次。比較用） | 273.4 ms |
| フィレット付きの箱のゼブラ表示 | 46.5 ms |

## わかったこと

- **曲面どうしのブーリアンが一番遅い**です（円柱 2 本で約 4.8 秒）。時間の大半は truck の交線計算です。厳密な交線もブーリアンを通すため、同じくらいかかります。メッシュから近似すれば 1 ms ですが、精度は表示メッシュの弦誤差（約 0.07 mm）までです。改善候補: 交線だけを求める処理をブーリアンから切り出すこと、リリースビルドで測ること、面の組を事前に絞り込むこと。
- 配列の並列化は、この 2 スレッドの環境では約 13% 速くなる程度でした（フィレットの 52 ms を含みます）。コア数の多い PC ではもっと効くはずですが、未計測です。
- 重い操作（ブーリアン・フィレット）は 1 回のカーネル呼び出しの中では止められません。キャンセルは呼び出しの前後と、配列の各組の間で確認しています。

- マシン: GitHub-hosted の ubuntu-24.04（Intel Xeon 6973P-C、4 スレッド、メモリ 16 GB）。上の表の環境（2 スレッド）とは違うので、**上の表と直接は比べられません**。
- コンパイラ: rustc 1.100.0、プロファイル `dev`（上と同じ。リリースビルドは未計測）。
- 測り方: `.github/workflows/nurbs-bench.yml`（`bench/**` ブランチに push すると `cargo run --example nurbs_benchmark` を実行）。各操作の最速値。

### わかったこと

- **表示メッシュの再利用**: B-rep を作るときにカーネルへ「メッシュを保持する」設定をしたので、稜線・面の一覧（フィレット・ブレンド・トリムで番号を点に直すときに呼ぶ）が、同じ許容差なら表示用に作ったメッシュを使い回します。20 回呼んでも合計 0.2 ms で、メッシュを作り直したときの時間（フィレット付きの箱で約 30 ms）より 2 桁以上小さい値です。ただし「再利用なし」との直接の比較は測っていません。
- **並列化**: 配列は 4 スレッドで逐次の約 1.5 倍の速さでした。ブーリアン・厳密な交線は 1 回のカーネル呼び出しの中なので、並列化も途中のキャンセルもまだできません（キャンセルは呼び出しの前後と配列の組の間で確認しています）。ここが一番遅い所（約 2.4〜3.3 秒）で、次の改善候補です。
- **表示メッシュの作成（テッセレーション）そのものの並列化は、今回は入れていません。** カーネルの表示計画（`tess::plan`）を直す必要があり、測定でボトルネックと確認できたブーリアン側を先に直すほうが効くと判断したためです。
