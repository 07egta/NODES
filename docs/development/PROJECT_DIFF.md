`nodes-cli diff` は、共通のノード ID を持つ `.morph` 作品の変更点を JSON で比較します。ノードの計算、ファイルの書き換え、形状の生成は行いません。並行して編集した作品や、保存前後の設定を確認するための機能です。

```sh
nodes-cli diff before.morph after.morph
nodes-cli diff before.morph after.morph 256
```

引数は変更前、変更後、任意の変更レコード開始位置です。開始位置は半角数字 `0`〜`9` で書く `0` 以上の整数で、省略時は `0` です。符号・小数点・全角数字は受け付けません。パスに空白がある場合は引用符で囲みます。

## 比較の意味

- 対応付けにはネイティブの `NodeId` を使用します。ノード配列の保存順が変わっても、追加・削除にはなりません。
- 同じ ID を引き継ぐリビジョン同士で使用します。別々に作った作品の同じ ID が、同じ意味のノードであるとは推定しません。形状の同一性やグラフ同型性を判定する機能ではありません。
- 計算に関係する保存フィールドは、ノード種類、無効化状態 `off`、数値パラメータ、入力接続です。
- 表示に関係するフィールドは、名前、キャンバス上の位置、プレビュー表示です。
- 数値パラメータは IEEE-754 のビットで比較し、`+0.0` と `-0.0` を区別します。差分には数値に加えて固定 16 桁の `ieee754_hex` を含めます。
- パラメータの未保存と、既定値の明示保存を区別します。現在の計算結果が同じになる場合も、保存設定の変更として記録します。計算結果が変化したという断定ではありません。
- 読み込みには既存の `graph_api::load_safe` を使います。旧ポート名などに対する既存の読み込み時正規化が先に行われるため、ファイルのバイト列そのものの比較ではありません。

ノードの完全な保存データ、スクリプト、メッシュ頂点、曲線サンプル、計算結果のデータツリーはレポートに含めません。各ノードには名前・種類・無効化状態・位置・プレビュー表示の小さな要約と、変更フィールドを記録します。

## 応答とページ分割

成功応答は通常の CLI エンベロープを使い、`result.diff` が比較レポートです。比較レポート自体の `schema_version` は `1` です。`cli_version`、Graph API のバージョン、ネイティブ作品のバージョンとは別の識別子です。

| フィールド | 意味 |
|---|---|
| `evaluation_performed` | 常に `false`。結果を得るためのノード評価は行わない |
| `has_changes` | ノードまたは作品メタデータに変更がある |
| `summary` | 追加・削除・変更・無変更のノード総数、計算設定と表示設定の変更件数 |
| `metadata` | 作品名、pan、zoom、next_id、グループ、メモの変更フラグ |
| `node_changes` | このページの変更ノード。ID 昇順で、追加・削除・変更を一つの並びにまとめる |
| `total_change_count` | 全ページにある追加＋削除＋変更ノードの正確な総数。作品メタデータの変更は含まない |
| `offset` / `page_size` | 今回の開始位置と固定ページサイズ `256` |
| `next_offset` | 続きの開始位置。最終ページでは `null` |
| `truncated` | このページの後に変更ノードが残っているとき `true` |
| `potential_dependency_impact` | 変更後グラフにおける接続上の潜在的な影響先 |

各呼び出しは最大 256 件の変更ノードを返します。`next_offset` の値を次の呼び出しの第 3 引数に渡すと、残りのノードを取り出せます。総数以上の開始位置は、総数を維持した空の最終ページを返します。固定ページサイズと正確な総数により、変更ノードが黙って取り落とされることを避けています。

各ノードのパラメータと入力接続の詳細は、それぞれ最大 64 件です。`parameter_change_count` / `input_change_count` は正確な件数、`parameters_truncated` / `inputs_truncated` は詳細の省略フラグです。現行の標準ノードの小さなポート構成を前提とした上限で、ノード詳細を無制限に出力しません。

`calculation_modified_count` と `presentation_modified_count` は、前後に同じ ID がある変更ノードを数えます。両方のフィールドを変えたノードは両方に含まれます。表示だけ変えた数は `presentation_only_count` です。追加・削除は別集計で、個別レコードでは存在の変化として計算・表示の両フラグを立てます。

## 潜在的な影響先

`potential_dependency_impact.meaning` は `"potential_dependency_impact"`、対象グラフは `"after"` です。

追加ノード、および計算設定が変わったノードを起点に、変更後の接続を下流へたどります。起点自身も含め、合流先と同一接続先の重複を除きます。無効ノードも接続上の候補に含めます。削除されたノードそのものは変更後グラフには存在しないため含みませんが、削除に伴い入力接続が変わった残存ノードは起点になります。

`seed_count` は起点数、`total_count` は重複を除いた正確な総数です。`node_ids` は ID 昇順で最大 256 件のプレビュー、`truncated` はプレビュー省略の有無です。影響先のプレビューは変更レコードのページ位置にかかわらず同じです。

この集合は、実際にキャッシュが無効化されたノードや、計算結果が変わったノードの一覧ではありません。今回の比較は評価器を起動せず、値が変わらない設定変更や無効ノードの実行挙動を推測しません。

## 読み込みと終了コード

両ファイルは、通常ファイルであること、8 MiB の読み込み上限、ネイティブ形式、グラフ整合性、既存 Graph API の許可範囲を検査します。スクリプト、式、外部ファイル読み込み、クラスタなど、既存 CLI が許可しない機能を含む作品は比較でも拒否します。拒否した内容を実行しません。

| 終了コード | 意味 |
|---|---|
| `0` | 比較成功。変更が見つかっても成功 |
| `1` | ファイルや作品が無効、読み込み失敗、許可されない内容など |
| `2` | 引数不足・過剰、負数・小数・範囲外などの不正な開始位置 |

構造検証に通るゼロ除算ノードなど、実行すると失敗する作品でも、比較だけなら成功します。`diff` が結果を出すために作品を保存したり、失敗する計算を動かしたりすることはありません。
