## リリースゲート（提案、今回はコード変更なし）
- OMEGA 79: THBを第一研究候補にし、基底・階層・truncation・抽出を独立設計。LRを比較。特許FTOが未確定の方式は新規公開実装しない。数学的な適合試験と請求項調査の両方が必要。
- OMEGA 80: UIと幾何バックエンドを分離。まずCatmull-Clark / 通常NURBS / 一方向変換。直接編集、Undo、安定IDは実装方式を監査。双方向リンク、非一様星点、trim-free変換はレビュー待ち。
- OMEGA 86: F04/F11を優先し星点の連続性・トポロジー変更の実装候補を請求項単位で照合。
- release owner: デフォルトOFFだけでは配布ソース・コンパイル済みコードのリスクを解消しない。専門家と既存公開履歴・バイナリ・依存に対する対応方針を決定。必要なら別途PRでCargo feature、ノード登録、保存時の互換診断、CLI/API・サンプル・配布アーカイブを含めて分離。履歴改変は独断で行わない。
- 合格条件: 公式国別状態、登録請求項ごとの照合表、出典記録、第三者ライセンス、専門家の確認範囲を記録。公開・無料・独立開発を特許免除と見なさない。
