# 保存・履歴・形状出力の実装範囲

この文書は `src/persistence.rs`、`src/templates.rs` の実装を説明する。動作確認結果はリリース時の検証記録を参照。

## プロジェクト

拡張子 `.morph` の中身はバージョン付き UTF-8 JSON。形式 v1 では作品名、ノードの安定 ID と種類、数値パラメータ、入力接続、ノード位置、プレビュー設定、キャンバス位置と拡大率を保存する。Rhino / Grasshopper の `.gh`、`.ghx`、`.3dm` とは別形式。

読み込みの上限は 8 MiB。未知の形式バージョン、未知のノード種別、不正な数値・接続・循環などは読み込みエラーとして返す。読込関数は現在編集中の作品へ直接書き込まない。UI は読み込みと検証が成功した後にだけ作品を置き換える。

保存は同じディレクトリに衝突しない一時ファイルを作り、書き込み・flush・sync を完了してから `std::fs::rename` で置き換える。元ファイルの事前削除は行わない。Windows で別のアプリが保存先を占有して置換に失敗する場合も、元のファイルを保持し、理由を返す。アプリ独自の `.bak` ファイルは作成しない。電源断やネットワーク共有上の挙動を完全に保証するものではない。

Undo/Redo は最大 64 回分の作品スナップショット。新たな編集を行うと Redo の分岐は破棄する。スライダーの一連のドラッグを 1 操作にまとめる判断は UI が担当する。

## STL と OBJ

- STL は三角形メッシュをバイナリ形式で出力する。80 バイトのヘッダー、32 bit little-endian の三角形数、1 面あたり 50 バイトの構成。法線と座標は 32 bit float、属性は 0。
- OBJ は三角形と頂点座標をテキストで出力する。複数のメッシュは別の `o` エントリーにし、面の頂点インデックスを各メッシュに応じてずらす。テクスチャ、材料、頂点カラーは書かない。
- アプリの座標単位は mm。STL のヘッダーと OBJ のコメントに単位を記すが、相手アプリがそのコメントを認識する保証はない。読み込む側でも mm を指定する。
- 出力対象はメッシュのみ。点・曲線・数値は出力せず、スキップ数を返す。メッシュがない場合は理由を表示する。
- 非有限座標、無効な頂点インデックス、面積 0 の面は書き出し前に検出する。STL は単精度へ丸めた後に面が潰れるケースも拒否する。元の出力ファイルは保持する。
- 頂点数・三角形数は出力全体でそれぞれ最大 2,000,000。通常はこれより小さいエンジン側上限が先に作用する。

## メッシュ検査の意味

`mesh_stats` は 0.000001 mm 単位へ座標を丸めて同じ位置の頂点を対応させ、境界辺、3 面以上で共有される辺、向きの食い違う共有辺、退化面を数える。境界箱と符号付き体積も返す。三角形メッシュの接続を確認する処理であり、最小肉厚、自己交差、重なった内部シェル、製造可否の完全な検査は行っていない。

`is_closed()` が true でも、実物の防水性や造形成功を意味しない。花器ノードの肉厚は半径方向の厚さで、複雑な凹凸における面への最短距離ではない。ねじり・波などの強い変形後はスライサーでの確認が必要。

## 編集可能なテンプレート

| 作品 | グラフ | 結果 |
|---|---|---|
| ねじれの花器 | 花器 → ねじり → 出力 | 底・内壁・外壁・上縁を持つメッシュ |
| 光のリング | 球 → 移動 → 円形配列 → 出力 | 独立した球の集合 |
| 星のトーテム | 星形 → 押し出し → ねじり → 出力 | 閉じたメッシュ |
| 螺旋のスケッチ | らせん → 出力 | 曲線。STL/OBJ のメッシュ出力対象外 |
| 波打つブロック | 箱 → 直線配列 → 波打つ → 出力 | 独立したブロックの集合 |
| 輪郭からロフト | 2 つの数列 → 円・移動 → ロフト → 出力 | 断面リストから生成したメッシュ |

## 12. G-code（花瓶モード・未検証）

この章は `src/gcode.rs` と `src/gcode_ui.rs` の説明です。コンパイルもテスト実行も実機の印刷もしていません。CIとテストが最初の確認で、初回の印刷は必ず見守ってください。STLが主な書き出しで、G-codeは補助機能です。

- 形状は閉じたメッシュを1つだけ受け付けます。層ごとに水平な面で切り、最大の外周だけを使います（内側の空洞は捨てます）。外周は約1 mmの間隔に割り直し、前の層の始点に最も近い点から始めます。
- 底は最低1層の平らな層で、設定した層数だけジグザグで塗りつぶします。その上は1周ごとにZが層の高さだけ上がる螺旋で、引き戻しは本体では行いません。
- 押し出し量は線幅×層の高さ×移動距離 ÷ フィラメント断面積で計算します。PLAの密度は 1.24 g/cm³ です。印刷時間は移動距離と速度から求めた目安で、加減速・加熱の待ち・一時停止は含みません。
- ベッドの大きさは機種プリセットの値です。実機の寸法と異なる場合は設定欄で直してください。FlashForge 汎用は最も小さい機種に合わせた値です。
- 出力は 64 MiB、層数は 3,000 層までです。超えた場合はエラーにして、既存のファイルは残します。
- 開始・終了のG-code（加熱、ホーム、捨て打ち線、引き戻し、ヒーターとファンの停止）は一般的な例です。機種の仕様と照らして確認してください。
- **Bambu Lab の機種では、Bambu Studio が書き出す .gcode.3mf が公式の方法です。** この生のG-code直接印刷は公式の手順ではなく、動作は確認していません。
- 螺旋の壁の厚みは1本の線幅です。強度や水密性は保証しません。
## 印刷向けの書き出し（STL・3MF・OBJ）

書き出しダイアログ（`src/stl_export_ui.rs`）と、その処理（`src/stl_export.rs`）。形式は STL バイナリ（既定）、STL テキスト、3MF（試験的）、OBJ。

- 単位: STL には単位がないため、常に mm で書き出す。倍率欄（×0.1・×10・×25.4 のボタン付き）で補正する。
- 置き方: 既定はベッドに置く（最低点を Z=0）。XY の中心合わせは既定で有効。
- 検査: 閉じている・面の向き・3枚以上の共有辺・つぶれた三角形・大きさ（1 mm 未満の警告、印刷機の大きさ超過のエラー）。厚さ・自己交差・造形可否は測らない。
- 自動修復（作品は変えない）: 近接頂点の統合、つぶれた面と重なった面の削除、BFS による向きそろえ（閉じた部品は外向きに）、周囲64辺以下の単純な穴を重心からの扇形でふさぐ。大きい穴は残す。
- 部品ごと: 頂点を共有する三角形で連結成分を分け、`名前_01.stl` などに書き分ける。
- 3MF: 単一オブジェクト、`unit="millimeter"`、無圧縮（stored）の ZIP を手組みで作成。CRC32 は自前実装。
- スライサー連携: 既定の場所（Bambu Studio・OrcaSlicer・PrusaSlicer）を探し、見つからなければ exe を一度選んで記憶する。起動は `Command` で exe に 1 引数（ファイル）を渡すだけで、シェルは使わない。
- すぐ書き出し（Ctrl+Shift+E）: 前回と同じファイルへ上書きする。スライサーの再読み込み用。
- 設定の保存先: Windows は `%APPDATA%\NODES\stl_export.json`、それ以外は `$XDG_CONFIG_HOME` または `~/.config` 配下。
- 既定の保存名の時刻は JST 固定（`<作品名>_<YYYYMMDD-HHMM>`）。

確認状況: コンパイルもテスト実行もしていません。CI が最初の確認になります。OrcaSlicer の exe 名（`orca-slicer.exe`）は未確認です。
