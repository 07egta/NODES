# NODES 実装言語方針

決定日: **2026-11-27 JST**。ユーザーの「Rust only を基本に、他の言語も少しはよい」という指示を、NODES共通の開発方針として記録する。

## 基本方針

**NODESはRustを主実装言語とする。必要な補助部分に限って、少量の他言語を使える。**

本体の新機能と既存機能の改善はRustで進める。Windows優先、日本語優先、軽量な独立型デスクトップという方針を維持し、ネイティブUIは既存のeframe/eguiを使う。通常の起動・編集・計算・保存にPython、Node.js、.NETやRhino/Grasshopperのインストールを要求しない。

言語の比率だけを目的とした一括移植は行わない。少量の例外とは、責務と接続箇所が限定され、本体のデータモデルや主要アルゴリズムを別言語へ移さないことを指す。別言語の大規模な幾何カーネルやUIへの置換は、この補助用途の例外には含めない。

## 適用範囲

| 部分 | 実装方針 |
|---|---|
| ノード評価、Data Tree、キャッシュ、非同期処理、標準ノード | Rust。共通の型と評価器を利用する |
| 数学、曲線、曲面、B-rep、メッシュ、生成デザイン | Rust。表示用近似と精密な幾何を分ける |
| GUI、ノードキャンバス、3D表示、検索、Undo/Redo | RustのネイティブUI。GPU用シェーダーが必要な場合は描画処理に限定する |
| 保存形式、移行、ファイル入出力、CLI、Graph API | Rust。既存の保存データと公開契約を維持する |
| 本体のテスト・ベンチマーク | Rustを基本とする。外部から結果を独立検証する補助スクリプトは許可する |
| 開発・配布・監査の補助 | Python、PowerShell、Shell等を必要な範囲で使える。本体の実行依存にしない |
| ユーザーが記述するスクリプト | 既存の制限付きRhaiと数式を維持する。ホスト側の評価・型変換・実行制限はRustで実装する |
| OS・外部機能との接続 | Rust APIを優先する。他言語が必要な場合は小さなアダプターへ局所化する |
| 設定、データ、ドキュメント、素材 | TOML、JSON、YAML、Markdown、フォント等は各用途に合った形式を使う |

外部の自動化クライアントがJSON API/CLIを他言語から利用することは許可する。標準機能をそのクライアントへ移したり、本体の実行に必須にしたりしない。

## 現在の構成と既存の例外

確認基点: `develop/nodes-ultimate` の `c52e850ed01a82461557fab9182778092151db2d`。
この時点の `src/` と `tests/` のソースはRustであり、GUI・計算・保存・CLIを別言語から移植する必要はない。

| 対象 | 役割と扱い |
|---|---|
| `scripts/audit_dependencies.py` | 開発時の依存宣言・ライセンス資料の照合。補助ツールとして維持 |
| `scripts/export_ci_checkpoint.py` | CI検証結果・復旧用情報の出力。補助ツールとして維持 |
| `scripts/update_gh2_inventory.py` | 公開資料から対応調査用の一覧を生成。補助ツールとして維持 |
| `scripts/validate_cli_vase.py` | CLIの外部実行と独立した出力検証。補助ツールとして維持 |
| `scripts/build-windows.ps1` | CargoによるWindowsビルドと配布準備の補助 |
| `.github/workflows/*.yml` | CI設定と短いShell/PowerShell/Pythonコマンド |
| `src/script.rs` とCargoの `rhai` 依存 | Rust側に組み込まれた既存のユーザースクリプト機能。実行制限と互換性を維持 |

Python/PowerShellは開発用であり、通常のアプリ利用の前提にはしない。Rhaiのスクリプト本文はユーザーのモデルに含まれる拡張で、NODES本体の標準ノードを他言語へ移す方針ではない。既存の `.morph` / `.morphpart` を言語方針だけを理由に書き換えたり、読み込めなくしたりしない。

Windows MSVC用のC++ Build Tools・Windows SDKや、OS・描画ライブラリを使うことは、NODESの本体をC++で開発することとは別である。第三者依存やツールチェーンの内部まで「100% Rust」とは宣言しない。`licenses/` のHTML等はライセンス資料であり、Web UIではない。

## 新しい例外を追加するとき

他言語を追加する変更では、PRに次を記録する。

1. その言語が必要な具体的な理由と、Rustで実装する案を採らない理由。
2. 対象ファイル・責務・Rustとの接続箇所。データモデルや主要計算はRust側へ残す。
3. 開発時だけ必要か、実行時にも必要か。任意機能なら無効時にも通常機能が使えること。
4. 配布サイズ、起動時間、メモリ、Windowsビルド、保守への影響。未計測は未計測と記す。
5. 依存・ライセンス・エラー処理・入力検証・必要な回帰確認。継続使用する例外はこの文書の一覧も更新する。

C/C++等との接続が必要になった場合も、FFIと所有権・寿命・スレッド・失敗時の扱いをRustの境界へ閉じ込める。既存のRhai機能を維持することは、別の汎用言語ランタイムを追加する根拠にはしない。将来のWasmホストやプラグインは未実装の検討項目であり、Rust主体の方針と実測した費用に照らして別途判断する。

## 依存とライセンス

Rustで書かれたcrateも、内部でネイティブライブラリやビルドツールを使用する場合がある。言語方針とライセンス確認は別々に扱い、[DEPENDENCIES.md](DEPENDENCIES.md) に依存・配布条件の確認範囲を残す。

本体のMIT OR Apache-2.0と、GPL/LGPL/AGPLの条件を採用しない既存方針を維持する。複数ライセンスの選択肢がある場合は、実際に選ぶ条件と根拠を記録する。既存の `r-efi` で記録したMIT選択や `smartstring` のMPL表示などを消さず、原文・通知・未確認事項を保持する。
